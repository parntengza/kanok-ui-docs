ใช้กับ framework ต่าง ๆ

component ทั้งหมดเป็น custom element มาตรฐาน (<ui-date-picker>, <ui-table> …) framework ไหนที่ render HTML ได้ก็ใช้ได้ ส่วน React มี wrapper ที่มี type ให้อีกชั้น หน้านี้รวมสิ่งที่ต่างกันในแต่ละ framework: การส่งข้อมูล การฟัง event การทำ routing การ render ฝั่ง server และภาษา

ตั้งค่า

  • React: ติดตั้งแพ็กเกจพร้อม Lit และ @lit/react ที่ wrapper ใช้อยู่เบื้องหลัง (React 19 ขึ้นไป) โหลด token ครั้งเดียว แล้ว import wrapper ที่ใช้
  • Vue: บอก compiler ของ Vue ว่า tag ที่ขึ้นต้นด้วย ui- เป็น custom element
  • Angular: เพิ่ม CUSTOM_ELEMENTS_SCHEMA ใน component ที่ใช้ element

  • HTML: เขียน attribute ใน markup ได้เลย ส่วน array, object และ function ให้ตั้งเป็น property ด้วย JavaScript และฟัง event ด้วย addEventListener
  • React: wrapper แต่ละตัว render element พร้อม prop ที่มี type prop จะตั้งค่าเป็น property ของ element จึงส่ง array, object และ function ได้ตรง ๆ ส่วน custom event กลายเป็น prop onUi… ที่มี type ของ detail
  • Vue: ผูก array และ object เป็น property ด้วย .prop และฟัง custom event ด้วยชื่อของมัน
  • Angular: [name] ผูก property, [attr.name] ผูก attribute และ (event-name) ฟัง event ได้ทุกชื่อ
  • แถวที่ framework render: ตารางเรียงลำดับด้วยการย้ายแถว ซึ่งเป็นของ framework จึงต้องเรียก preventDefault() ใน ui-table-header-cell-sort เรียงข้อมูลเอง แล้วตั้ง sort-direction ของหัวคอลัมน์ แบบด้านบน (Data table)

input และ change ใน React

ช่องกรอกยิง event input และ change แบบ native ตามความหมายของ DOM: onInput ทุกครั้งที่พิมพ์ ส่วน onChange เมื่อผู้ใช้ยืนยันค่า (ออกจากช่อง กด Enter หรือเลือกวันที่) ต่างจาก <input onChange> ของ React ที่ยิงทุกครั้งที่พิมพ์

ชื่อ prop ตาม event ที่ element ยิงจริง date picker ยิง change จึงใช้ onChange และ UiDatePicker ไม่มี onUiChange ดู event prop ของแต่ละ wrapper ได้จาก autocomplete ของ editor

ใช้ attribute หรือ property?

ค่า ส่งอย่างไร
ข้อความ ตัวเลข (label, max-count) attribute หรือ property ก็ได้
เปิด / ปิด (required, disabled) มีหรือไม่มี attribute หรือ property แบบ boolean
array, object, function (rows, headers, isDateDisabled) property เท่านั้น

attribute ใช้ขีด (invalid-text) ส่วน property ใช้ camelCase (invalidText) API reference มีทั้งสองแบบของทุก element

ให้ SPA router เปลี่ยนหน้าเมื่อคลิกลิงก์

ลิงก์ที่ component วาดเองอยู่ใน shadow DOM ซึ่ง router ฝั่ง client มองไม่เห็น การคลิกปกติจึงยิง event ui-navigate ที่ยกเลิกได้พร้อม { href } ก่อน ยกเลิก event แล้วให้ router เปลี่ยนหน้าเอง ฟังที่ document ที่เดียวก็ครอบคลุมทั้งแอป

element ที่ยิง event นี้: ui-header-name, ui-header-menu-item, ui-side-nav-link, ui-side-nav-menu-item, ui-switcher-item, ui-link, ui-breadcrumb-item และ ui-button, ui-icon-button, ui-tile, ui-card, ui-tree-node เมื่อมี href

ReactVueAngular// React Router import { useEffect } from 'react'; import { useNavigate } from 'react-router'; import type { NavigateDetail } from '@purpurabog/ui/react'; export function useUiNavigate() { const navigate = useNavigate(); useEffect(() => { const onNavigate = (event: CustomEvent<NavigateDetail>) => { event.preventDefault(); navigate(event.detail.href); }; document.addEventListener('ui-navigate', onNavigate); return () => document.removeEventListener('ui-navigate', onNavigate); }, [navigate]); } // Vue Router import { router } from './router'; document.addEventListener('ui-navigate', (event) => { event.preventDefault(); router.push(event.detail.href); }); // Angular Router import { Component, HostListener, inject } from '@angular/core'; import { Router, RouterOutlet } from '@angular/router'; import type { NavigateDetail } from '@purpurabog/ui'; @Component({ selector: 'app-root', standalone: true, imports: [RouterOutlet], template: '<router-outlet />', }) export class AppComponent { private readonly router = inject(Router); @HostListener('document:ui-navigate', ['$event']) onNavigate(event: CustomEvent<NavigateDetail>) { event.preventDefault(); this.router.navigateByUrl(event.detail.href); } }

ใน React ให้เรียก useUiNavigate() ครั้งเดียวใน layout หลัก ถ้าต้องการจัดการเฉพาะลิงก์เดียวหรือเมนูเดียว wrapper มี prop onUiNavigate ให้ด้วย: บน wrapper ของลิงก์ทุกตัว และบน UiHeader, UiSideNav, UiHeaderMenu, UiSideNavMenu ที่ event bubble ผ่าน

กรณีที่ router ไม่ได้รับ event

  • คลิกพร้อม Ctrl, ⌘, Shift หรือ Alt, คลิกปุ่มกลาง, target="_blank", download และลิงก์ไปเว็บอื่น ไม่ยิง ui-navigate ลิงก์ทำงานตามปกติ จึงยังเปิดในแท็บใหม่ได้
  • ถ้าไม่มีใครยกเลิก event ลิงก์จะโหลดหน้าใหม่ตามปกติ จะเพิ่ม listener ทีหลังก็ไม่มีอะไรพัง
  • ระบุหน้าปัจจุบันเอง เช่น current บน ui-side-nav-link ส่วน ui-header-menu จะแสดงแถบหน้าปัจจุบันเองเมื่อมีลิงก์ข้างในที่เป็น current

Render ฝั่ง server

ทุก element render ฝั่ง server ด้วย Lit SSR ได้ (@lit-labs/ssr หรือผ่าน @lit-labs/nextjs, @lit-labs/eleventy-plugin-lit, @astrojs/lit ของ Astro) HTML จาก server เป็น first paint พอ JavaScript โหลดเสร็จ แต่ละ element จะ render shadow root ใหม่ทับแทนการ hydrate จึงไม่มีปัญหา hydration mismatch

import { render } from '@lit-labs/ssr'; import { collectResult } from '@lit-labs/ssr/lib/render-result.js'; import { html } from 'lit'; import '@purpurabog/ui/date-picker'; const field = await collectResult(render(html`<ui-date-picker lang="th" label="วันที่เริ่มสัญญา" name="start"></ui-date-picker>`));

import @lit-labs/ssr ก่อน element เสมอ เพราะมันติดตั้ง DOM shim ที่ element ต้องใช้

server มองไม่เห็นบางอย่าง first paint จึงยังไม่ครบจนกว่า JavaScript จะทำงาน:

  • ลูกใน light DOM: <ui-select> ยังไม่มีรายการ และ ui-tabs ยังแสดงทุก panel
  • property: rows, headers, files
  • ancestor รวมถึง <html lang>: ข้อความในตัวเป็นภาษาอังกฤษ ถ้า element ไม่มี lang ของตัวเอง ใส่ lang="th" ที่ element ถ้าต้องการ first paint เป็นภาษาไทย
  • attribute สถานะอย่าง data-show-error และ data-open ซึ่งตั้งใน browser

ถ้าไม่อยากให้หน้ากะพริบเป็นธีมสว่างก่อนเปลี่ยนเป็นธีมที่ผู้ใช้เลือกไว้ ใส่ theme script ใน <head> ก่อน CSS:

import { themeScript } from '@purpurabog/ui/core'; const head = `<script>${themeScript({ storageKey: 'ui-theme' })}</script>`;

storageKey ต้องตรงกับ storage-key ของ <ui-theme-switcher> (ค่าเริ่มต้น ui-theme) ถ้า switcher ตั้ง light-theme หรือ dark-theme ให้ส่งค่าเดียวกันเป็น lightTheme และ darkTheme (ค่าเริ่มต้น white และ g100)

ใช้ใน shadow root (micro app)

ถ้าแอปของคุณถูกฝังในหน้าของคนอื่น ให้ mount แอปใน shadow root ของ custom element ตัวเดียว แล้วใส่ CSS ทั้งหมดไว้ข้างใน style จะไม่รั่วเข้าหรือออก component แบบ React + Tailwind รองรับแบบนี้แล้ว:

import css from './app.css?inline'; // Vite: CSS ที่ build แล้วในรูปข้อความ import { createRoot } from 'react-dom/client'; import { App } from './App'; class ContractsApp extends HTMLElement { connectedCallback() { const shadow = this.shadowRoot ?? this.attachShadow({ mode: 'open' }); const sheet = new CSSStyleSheet(); sheet.replaceSync(css); shadow.adoptedStyleSheets = [sheet]; const mount = document.createElement('div'); shadow.append(mount); createRoot(mount).render(<App />); } } customElements.define('contracts-app', ContractsApp);

app.css มี Tailwind, token และธีม:

@import 'tailwindcss'; @import './components/ui/primitives/tokens.css'; @import './components/ui/react-tw/theme.css';
  • tokens.css ประกาศ token ทุกตัวทั้งบน :root และ :host จึงใช้ใน shadow root ได้ web component ก็ใช้ไฟล์เดียวกันนี้ได้
  • สลับธีมด้วย data-theme บน element ที่เป็น host (<contracts-app data-theme="g100">) เพราะตัวเลือกธีมเปลี่ยนแค่ที่ <html>
  • ถ้าใช้ดีไซน์ Kanok ให้ import ./components/ui/primitives/kanok.css ต่อจาก token และใส่ data-design="kanok" ที่ element ที่เป็น host ด้วย
  • ประกาศฟอนต์ (@font-face) ที่ระดับ document เพราะ Chrome ไม่โหลด @font-face ที่อยู่ใน shadow root

ใส่ type ให้ event listener

ทุก element มี Ui…EventMap และ addEventListener รู้ type ของ detail ตามชื่อ event ส่วน document.querySelector('ui-table') ได้ type ของ element นั้นเลย:

const table = document.querySelector('ui-table')!; table.addEventListener('ui-table-row-selected', (e) => console.log(e.detail.selectedRow, e.detail.selectedRows));

ถ้าต้องการเรียกชื่อ type ของ detail ก็ import ได้:

import type { MenuSelectDetail, NavigateDetail, OpenDetail, TableSortedDetail } from '@purpurabog/ui';

ui-navigate ประกาศไว้บน document ด้วย listener ของ router ข้างบนจึงมี type โดยไม่ต้อง cast

ควรฟังที่ตัว element เอง ไม่ใช่ที่ container เพราะ event ui-* bubble และข้าม shadow root ได้ container จึงได้ ui-toggle จากทุก component ข้างใน

ข้อความไทยและอังกฤษ

ข้อความในตัว component (ชื่อปุ่ม ข้อความ required ตัวนับ ชื่อเดือน) ใช้ lang ที่ใกล้ที่สุด: ของ element เอง, ancestor ที่ใกล้ที่สุด, <html> แล้วจึงเป็นภาษาของ browser มีไทยและอังกฤษให้แล้ว ภาษาอื่นจะใช้ภาษาอังกฤษแทน

<html lang="th"> … <section lang="en"> <ui-date-picker label="Start date" name="start"></ui-date-picker> </section> </html>

เปลี่ยน lang ที่ <html> หรือที่ตัว element ระหว่างใช้งาน แล้ว element จะ render ใหม่เป็นภาษาใหม่

ถ้าจะเปลี่ยนข้อความบางตัว ให้ register สำเนาของคำแปลที่มีอยู่ พร้อมข้อความที่แก้:

import { getTranslation, registerTranslation } from '@purpurabog/ui'; const th = getTranslation('th'); registerTranslation({ ...th, datePicker: { ...th.datePicker, required: 'กรุณาเลือกวันที่เริ่มสัญญา' } });

เพิ่มภาษาใหม่ก็ทำแบบเดียวกัน ใส่ $code ใหม่ (เช่น $code: 'ja') และแปลทุกข้อความ ดู key ทั้งหมดได้จากข้อความภาษาอังกฤษใน src/core/translations/en.ts

attribute ข้อความบน element ชนะคำแปลเสมอ เช่น required-text, too-long-text หรือ close-label wrapper ของ React ก็ export registerTranslation และ getTranslation ให้ด้วย
