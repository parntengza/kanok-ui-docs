File uploader

ปุ่มหรือพื้นที่วางไฟล์

ค่าเริ่มต้นเป็นปุ่ม "เพิ่มไฟล์" แบบ Carbon ถ้าตั้ง drop จะเป็นพื้นที่วางไฟล์เส้นประแทน (FileUploaderDropContainer ของ Carbon) ผู้ใช้ลากไฟล์มาวาง หรือคลิกเพื่อเปิดหน้าต่างเลือกไฟล์ก็ได้ ถ้าลากโฟลเดอร์มาวาง โฟลเดอร์จะถูกข้ามไป

  • button-label เปลี่ยนข้อความบนปุ่ม button-kind เปลี่ยนชนิดปุ่ม (ค่าเริ่มต้น primary) หลังเลือกไฟล์ ปุ่มจะแสดงชื่อไฟล์ หรือ "3 ไฟล์" ถ้าอยากให้ข้อความเดิมอยู่ตลอด ให้ตั้ง keep-label
  • drop-label เปลี่ยนข้อความในพื้นที่วางไฟล์
  • size (sm, md, lg) กำหนดขนาดปุ่มและแถวรายการ

จำกัดไฟล์

  • accept ระบุชนิดไฟล์ เป็นนามสกุลหรือ MIME type คั่นด้วยจุลภาค (.pdf,.jpg,image/png)
  • max-file-size คือขนาดสูงสุดของไฟล์หนึ่งไฟล์ หน่วยเป็นไบต์ (5 MB = 5000000)
  • max-files คือจำนวนไฟล์สูงสุดในรายการ และ max-total-size คือขนาดรวมสูงสุดเป็นไบต์ สองอย่างนี้ไม่มีใน Carbon

ไฟล์ที่ไม่ผ่านเงื่อนไขยังอยู่ในรายการ แต่ขึ้นเป็น error พร้อมเหตุผล ผู้ใช้จึงเห็นว่าเกิดอะไรขึ้น ไฟล์นี้ไม่ถูกส่งไปกับฟอร์ม และผู้ใช้ลบออกได้ด้วยปุ่ม × เปลี่ยนหัวข้อ error ได้ด้วย invalid-type-text, too-large-text, too-many-text และ total-too-large-text ส่วนบรรทัดใต้หัวข้อเปลี่ยนด้วย invalid-body-text ข้อความในตัวแปลตามภาษาของหน้า ("ไม่รองรับไฟล์ประเภทนี้", "ไฟล์มีขนาดใหญ่เกินไป", "จำนวนไฟล์เกินกำหนด" …)

สถานะของไฟล์

แต่ละแถวแสดงสถานะใดสถานะหนึ่งต่อไปนี้ แถวใช้แยกเดี่ยว ๆ ได้ด้วย สำหรับไฟล์ที่อยู่บน server แล้ว แถวจะยิง ui-delete และ ui-retry ส่วนการเอาแถวออกจากหน้าเป็นหน้าที่ของคุณ

  • uploading: แสดง spinner หรือถ้ามี progress จะแสดงเปอร์เซ็นต์ แถบความคืบหน้า และปุ่ม × สำหรับยกเลิก

ไฟล์ที่อยู่บน server แล้ว

ถ้ารายการนั้นมีไฟล์อยู่แล้ว ให้ใส่ไฟล์เหล่านั้นใน uploader เป็นลูก <ui-file-uploader-item> (FileUploaderItem ใน React + Tailwind) แถวเหล่านี้แสดงต่อจากไฟล์ที่ผู้ใช้เลือก ปุ่ม × ของแถวยิง ui-delete ที่ตัวแถวเอง: ให้เอาแถวออกและลบไฟล์บน server event นี้ผ่าน uploader ออกมาตามเดิม จึงต้องฟังที่แถว ไม่ใช่รอ ui-delete ของ uploader

ใช้ในฟอร์ม

  • ถ้าใส่ name ไฟล์ที่ผ่านเงื่อนไขทุกไฟล์จะถูกส่งไปภายใต้ชื่อนั้น เหมือน <input type="file" multiple> ไฟล์ที่ไม่ผ่านเงื่อนไขจะไม่ถูกส่ง
  • required ทำให้ฟอร์มส่งไม่ได้จนกว่าจะมีไฟล์ที่ผ่านเงื่อนไขอย่างน้อยหนึ่งไฟล์ เปลี่ยนข้อความได้ด้วย required-text ดูเพิ่มที่ ฟอร์มและการตรวจค่า
  • การ reset ฟอร์มจะล้างรายการไฟล์ disabled หรือ fieldset ที่ปิดใช้งานจะปิดทุกอย่าง

อัปโหลดไฟล์

file uploader ไม่ได้อัปโหลดเอง มันแค่แสดงรายการไฟล์ แล้วคุณเป็นคนส่ง ให้อัปเดตรายการตามความคืบหน้าของแต่ละไฟล์ โดยแทนที่ files ด้วย array ใหม่ แล้วแต่ละแถวจะแสดงตาม status ของไฟล์นั้น

  • uploading แสดง spinner ถ้ามี progress (0–100) จะแสดงเปอร์เซ็นต์และแถบเล็ก ๆ แทน และปุ่ม × จะเป็นการยกเลิกอัปโหลด: ไฟล์ถูกเอาออกจากรายการ และ ui-delete บอกให้คุณหยุดส่ง
  • complete แสดงเครื่องหมายถูก และ screen reader อ่านว่า "อัปโหลดแล้ว: contract.pdf"
  • status ที่ตัว uploader กำหนดสถานะเริ่มต้นของไฟล์ใหม่ (ค่าเริ่มต้น edit ซึ่งมีปุ่ม ×)

ลองเลือกไฟล์ด้านล่าง แต่ละไฟล์จะอัปโหลดทันที การอัปโหลดในตัวอย่างนี้เป็นตัวแทนที่เดินตามเวลา และไฟล์ที่ชื่อมีคำว่า "fail" จะล้มเหลวครึ่งทาง ให้ลองกดอัปโหลดใหม่

คีย์บอร์ด

ปุ่ม ผล
Enter หรือ Space ที่ปุ่มหรือพื้นที่วางไฟล์ เปิดหน้าต่างเลือกไฟล์
Enter หรือ Space ที่ปุ่ม × ลบไฟล์หรือยกเลิกการอัปโหลด โฟกัสย้ายไปที่ปุ่ม × ของไฟล์ถัดไป ถ้าไม่มีไปที่ไฟล์ก่อนหน้า ถ้าไม่มีอีกไปที่ปุ่มเลือกไฟล์
Enter หรือ Space ที่ปุ่มลองใหม่ ยิง ui-retry

Accessibility

  • ตัว uploader เป็น group ที่ใช้ label-title เป็นชื่อ และ file input ที่ซ่อนอยู่ก็ใช้ชื่อนี้เช่นกัน
  • ปุ่ม × และปุ่มลองใหม่มีชื่อไฟล์อยู่ในชื่อปุ่ม: "ลบไฟล์ - contract.pdf", "ลองอัปโหลดอีกครั้ง - contract.pdf"
  • error เป็น alert ถูกอ่านทันทีที่ขึ้น และเมื่ออัปโหลดเสร็จจะมีการอ่านแจ้ง เพราะ spinner ที่เปลี่ยนเป็นเครื่องหมายถูกไม่มีเสียง
  • แถบความคืบหน้าเป็น progressbar ที่ screen reader ถามค่าได้ แต่เปอร์เซ็นต์ไม่ถูกอ่านทุกครั้งที่เปลี่ยน

ต้องการแค่พฤติกรรมโดยไม่มี style: Headless File uploader
