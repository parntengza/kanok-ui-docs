ปรับแต่งหน้าตา

เริ่มจากชั้นที่ตื้นที่สุดก่อน แล้วค่อยลงลึกเมื่อชั้นนั้นไม่พอ:

  1. Design token (--ui-*) สำหรับขนาดและสี
  2. โซนธีม (data-theme ดู ธีมและ layer)
  3. ::part() สำหรับชิ้นส่วนเดียวของ element
  4. Slot สำหรับใส่ markup ใน label และข้อความช่วยเหลือ
  5. Derive class เป็นทางสุดท้าย

ชั้นที่ตื้นกว่ารอดการอัปเกรดได้ดีกว่า เพราะไม่ผูกกับโครงสร้างภายในของ element attribute, property, event, slot, part และ token --ui-* ที่อยู่ใน api.md จะไม่ถูกลบหรือเปลี่ยนชื่อก่อน major version ถัดไป ส่วน selector ภายใน shadow DOM ไม่อยู่ในข้อตกลงนี้

เปลี่ยนขนาดและสีด้วย token

ทุก component อ่าน CSS custom property ชื่อ --ui-* จาก tokens.css (โหลดครั้งเดียวต่อหน้า) ตั้งที่ :root เพื่อเปลี่ยนทั้งแอป หรือตั้งที่ element ใดก็ได้เพื่อเปลี่ยนเฉพาะสิ่งที่อยู่ข้างใน ไม่ต้องแตะ shadow DOM เลย:

HTMLReactReact + Tailwind<style> .compact { --ui-field-height-md: 32px; --ui-menu-max-rows: 3; } </style> <div class="compact"> <ui-text-input label="ช่องสูง 32px"></ui-text-input> <ui-dropdown label="เมนูแสดง 3 แถว" placeholder="เลือก"> <option value="1">หนึ่ง</option> <option value="2">สอง</option> <option value="3">สาม</option> <option value="4">สี่</option> </ui-dropdown> </div> // .compact คือกฎ CSS เดียวกับในแท็บ HTML <div className="compact"> <UiTextInput label="ช่องสูง 32px" /> <UiDropdown label="เมนูแสดง 3 แถว" placeholder="เลือก"> <option value="1">หนึ่ง</option> <option value="2">สอง</option> <option value="3">สาม</option> <option value="4">สี่</option> </UiDropdown> </div> const numbers = [ { value: '1', label: 'หนึ่ง' }, { value: '2', label: 'สอง' }, { value: '3', label: 'สาม' }, { value: '4', label: 'สี่' }, ]; <div className="[--ui-field-height-md:32px] [--ui-menu-max-rows:3]"> <TextInput label="ช่องสูง 32px" /> <Dropdown label="เมนูแสดง 3 แถว" placeholder="เลือก" items={numbers} /> </div>

class ของ React + Tailwind อ่าน token ชุดเดียวกัน (ดูด้านล่าง) token ที่ตั้งบน element ครอบจึงเปลี่ยนมันได้ด้วย ส่วน part ของ headless ไม่มีหน้าตาของตัวเอง token จึงไม่มีผล

token สาธารณะที่ component อ่าน:

Token เปลี่ยนอะไร
--ui-field-height-sm, -md, -lg ความสูงช่องตาม size (32 / 40 / 48px): text input, select, dropdown, combobox, multi-select, date picker, button
--ui-menu-max-rows จำนวนแถวที่เมนูของ dropdown, combobox หรือ multi-select แสดงก่อนเลื่อน (5.5)
--ui-sheet-radius มุมด้านบนของ bottom sheet ของ date picker บนมือถือ (ค่าเริ่มต้นเท่ากับความมนของเมนู)
--ui-available-height, --ui-available-width เขียนลงบนรายการหรือเมนูขณะเปิด: พื้นที่ที่เหลือข้างช่อง max-height ของรายการใช้ค่านี้ รายการยาว ๆ จึงเลื่อนอยู่ในจอ อ่านค่านี้ใน CSS ของ popup ของคุณเองได้ แต่อย่าตั้งค่าเอง
--ui-calendar-width ความกว้างปฏิทินของ date picker (288px)
--ui-highlight สีของวันที่ที่เลือกใน range picker
--ui-surface-1, --ui-surface-2, --ui-hairline, --ui-ink-subtle, --ui-ghost-hover, --ui-ghost-active token ของ layer: ชี้ไปที่ชุดสีของชั้นปัจจุบัน และ <ui-layer> เป็นตัวเลื่อนให้
--ui-primary, --ui-ink, --ui-canvas, --ui-focus, … สีระดับธีม แต่ละตัวสร้างจาก token ของ Carbon ที่เขียนไว้ท้ายบรรทัดใน tokens.css

รายการ token ของแต่ละ element อยู่ในหัวข้อ "Design tokens" ใน api.md และในตาราง CSS custom properties ของหน้านั้นใน Storybook

แก้ชิ้นส่วนเดียวของ element ด้วย ::part()

::part(ชื่อ) แต่งชิ้นส่วนที่ element เปิดให้แต่ง ชื่อ part เป็นคำเดียวกันทุก component: base, label, input, menu, option, helper-text, error-text, … date picker ส่ง part ของช่องข้างในออกมาให้ด้วย และในโหมด range จะมี start- กับ end- นำหน้า:

HTMLReact<style> ui-dropdown.bold::part(input) { font-weight: 600; } ui-date-picker.split::part(end-input) { text-align: end; } </style> <ui-dropdown class="bold" label="ตัวหนา" placeholder="เลือก"> <option value="1">หนึ่ง</option> </ui-dropdown> <ui-date-picker class="split" range label="เริ่ม" end-label="สิ้นสุด"></ui-date-picker> // CSS เดียวกับในแท็บ HTML เพราะ wrapper render <ui-dropdown> และ <ui-date-picker> <UiDropdown className="bold" label="ตัวหนา" placeholder="เลือก"> <option value="1">หนึ่ง</option> </UiDropdown> <UiDatePicker className="split" range label="เริ่ม" endLabel="สิ้นสุด" />

part ของทุก element อยู่ใน api.md ::part() ใช้กับ web component และ wrapper ของ React ที่ render มัน ส่วน React + Tailwind และ headless ไม่มี shadow DOM ให้ใส่ class ที่ชิ้นส่วนแทน (สองหัวข้อสุดท้าย)

บาง element ไม่มีชิ้นส่วนข้างใน: ui-toaster, ui-fluid-form, ui-button-set, ui-badge-indicator และ ui-stack คือกล่องที่เห็นทั้งกล่อง ให้แต่งด้วย CSS ธรรมดาที่ตัว element เช่น ui-stack { row-gap: 24px; } หรือ ui-badge-indicator { background: var(--ui-info); } CSS ของหน้าเว็บชนะสไตล์ของมันเอง ui-button-set มี part button-set ด้วย (ตาม Carbon) แต่ layout อยู่ที่ตัว element

แต่งตามสถานะ

ทุกสถานะที่มีผลกับหน้าตาอ่านได้จากตัว element เอง และใช้คู่กับ ::part() ได้:

  • property ที่คุณหรือผู้ใช้เปลี่ยน จะ reflect เป็น attribute: open, checked, selected, expanded, invalid, warn, size, kind, …
  • สถานะที่ element คำนวณเอง ตั้งเป็น attribute data-* บนตัว element:
Attribute ความหมาย อยู่บน
data-open รายการหรือปฏิทินเปิดอยู่ ui-dropdown, ui-combobox, ui-multi-select, ui-date-picker
data-show-error, data-show-warn error หรือคำเตือนแสดงอยู่จริง (error แสดงแทนคำเตือน) ช่องฟอร์มทุกตัว
data-has-value มีข้อความหรือมีตัวเลือกแล้ว ui-combobox, ui-multi-select, ui-search
data-placeholder กำลังแสดง placeholder ui-dropdown, ui-select
data-password-visible รหัสผ่านกำลังแสดงอยู่ ui-text-input type="password"
data-editing อยู่ในโหมดแก้ไข ui-edit-in-place
data-drag-over กำลังลากไฟล์อยู่เหนือพื้นที่วาง ui-file-uploader
data-shown spinner หรือ overlay แสดงจริง (หลัง delay) ui-loading
data-overflowing ข้อความถูกตัดอยู่ ui-truncated-text

ทุกค่าในตารางนี้เป็น custom state ด้วย แบบเดียวกับ element ของเบราว์เซอร์และ Web Awesome: ui-dropdown:state(open) ตรงกับ ui-dropdown[data-open] ทุกครั้ง (:state(show-error), :state(has-value) …) ใช้แบบไหนก็ได้ ส่วน attribute ใช้ได้กับเบราว์เซอร์รุ่นเก่าด้วย state ของแต่ละ element อยู่ใน API reference ของมัน

ลองคลิกที่ช่องอีเมลแล้วออกโดยไม่กรอก จากนั้นเปิด dropdown:

HTMLReact<style> ui-text-input[data-show-error]::part(label) { color: var(--ui-error-text); } ui-dropdown[data-open]::part(label) { font-weight: 600; } </style> <ui-text-input label="อีเมล" required></ui-text-input> <ui-dropdown label="ผลไม้" placeholder="เลือก"> <option value="1">แอปเปิล</option> </ui-dropdown> // CSS เดียวกับในแท็บ HTML เพราะสถานะถูกตั้งบน element ที่ wrapper render <UiTextInput label="อีเมล" required /> <UiDropdown label="ผลไม้" placeholder="เลือก"> <option value="1">แอปเปิล</option> </UiDropdown>

ถ้าจะแต่งตาม error ที่ผู้ใช้เห็นจริง ใช้ [data-show-error] แทน [invalid] เพราะ invalid คือค่าที่คุณตั้งเอง มันยังอยู่แม้ช่องจะ disabled ซึ่งไม่แสดง error และไม่รวม error ที่เกิดจากสิ่งที่ผู้ใช้กรอก

data-* ถูกตั้งหลัง render ครั้งแรกใน browser HTML ที่ render มาจาก server จึงยังไม่มี attribute เหล่านี้ ส่วน part ของ headless แสดงสถานะด้วย attribute data-* ชุดของตัวเอง ดูที่ Headless

ใส่ markup ใน label และข้อความช่วยเหลือด้วย slot

เมื่อข้อความต้องมีลิงก์ ตัวหนา หรือไอคอน ให้ใช้ slot แทน attribute ชื่อเดียวกัน attribute ยังใช้เป็นข้อความธรรมดาสำรองได้เหมือนเดิม

อีเมล (จำเป็น) ใช้อีเมลบริษัท ดูนโยบาย
HTMLReactReact + Tailwind<ui-text-input> <span slot="label">อีเมล <em>(จำเป็น)</em></span> <span slot="helper-text">ใช้อีเมลบริษัท ดู<a href="#policy">นโยบาย</a></span> </ui-text-input> <ui-dropdown label="ประเทศ" placeholder="เลือก"> <option value="th" data-description="UTC+7">ไทย</option> <option value="jp" data-description="UTC+9">ญี่ปุ่น</option> </ui-dropdown> <UiTextInput> <span slot="label">อีเมล <em>(จำเป็น)</em></span> <span slot="helper-text">ใช้อีเมลบริษัท ดู<a href="#policy">นโยบาย</a></span> </UiTextInput> <UiDropdown label="ประเทศ" placeholder="เลือก"> <option value="th" data-description="UTC+7">ไทย</option> <option value="jp" data-description="UTC+9">ญี่ปุ่น</option> </UiDropdown> const countries = [ { value: 'th', label: 'ไทย', description: 'UTC+7' }, { value: 'jp', label: 'ญี่ปุ่น', description: 'UTC+9' }, ]; <TextInput label={<>อีเมล <em>(จำเป็น)</em></>} helperText={<>ใช้อีเมลบริษัท ดู<a href="#policy">นโยบาย</a></>} /> <Dropdown label="ประเทศ" placeholder="เลือก" items={countries} />

ช่องกรอกทุกตัวรับ slot label, helper-text, warn-text และ invalid-text ส่วน data-description บน <option> เพิ่มบรรทัดที่สองใน dropdown, combobox หรือ multi-select element อื่นมี slot ของตัวเอง เช่น header-actions ของ ui-modal และ end ของ ui-tabs ดูทั้งหมดได้ใน api.md React + Tailwind ไม่มี slot แต่ label, helperText, warnText และ invalidText รับ markup ได้ และ description ของ item คือบรรทัดที่สอง

เปลี่ยนรูปทรงด้วย derive class

ทางสุดท้าย สำหรับสิ่งที่ token, part และ slot ทำไม่ได้ และใช้ได้เฉพาะ web component ให้สืบทอด class ของ element แล้วต่อ style ของคุณท้าย style เดิม พฤติกรรมทั้งหมด (ฟอร์ม คีย์บอร์ด accessibility) ยังได้มาครบ:

import { css } from 'lit'; import { UiButton } from '@purpurabog/ui/button'; export class BrandButton extends UiButton { static override readonly styles = [ ...UiButton.styles, css` [part='base'] { border-radius: var(--ui-radius-pill); } `, ]; } customElements.define('brand-button', BrandButton); declare global { interface HTMLElementTagNameMap { 'brand-button': BrandButton; } }

selector ภายในไม่ใช่ public API ให้เลือกด้วย [part=…] แบบข้างบน ซึ่งทนการอัปเกรดได้ดีกว่าชื่อ class ภายใน

React + Tailwind: แก้ class ในไฟล์ที่ copy มา

shadcn copy source ของ component เข้ามาในแอป คุณจึงแก้หน้าตาได้ตรงที่มันเขียนไว้เลย แต่ละไฟล์เก็บ class เป็น Tailwind ธรรมดา (variant ของ kind และ size อยู่ใน cva) เช่นใน components/ui/react-tw/button.tsx:

// ก่อน 'rounded-none border border-solid border-transparent', // หลัง: ปุ่มทุกตัวเป็นทรงแคปซูล 'rounded-pill border border-solid border-transparent',

ถ้าจะเปลี่ยนแค่จุดเดียว ส่ง className เข้าไป class จะถูกรวมด้วย tailwind-merge ตัวที่คุณส่งจึงชนะ:

import { Button } from '@/components/ui/react-tw/button'; <Button className="w-full">บันทึก</Button>

class ต่าง ๆ (bg-primary, text-ink, h-field-md, rounded-pill, …) มาจาก theme.css ซึ่งแปลง token --ui-* เป็น theme ของ Tailwind ทั้ง token และโซน data-theme จึงใช้ได้เหมือนกับ web component ทุกอย่าง ส่วนพฤติกรรม (คีย์บอร์ด โฟกัส ARIA) มาจาก @purpurabog/ui/headless และอัปเดตตามแพ็กเกจต่อไป

Headless

ชิ้นส่วนของ headless ไม่ render class และไม่อ่าน token คุณแต่งเองจาก attribute data-* ที่บอกสถานะ ดูที่ Headless
