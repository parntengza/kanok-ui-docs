สกุลเงิน หน่วย และ mask

prefix-text และ suffix-text ใส่ข้อความไว้ในช่อง หน้าหรือหลังค่า เช่น สกุลเงินหรือหน่วย ข้อความนี้ไม่เป็นส่วนของค่า และ screen reader อ่านเป็นส่วนหนึ่งของคำอธิบายช่อง

mask จัดรูปแบบค่าระหว่างพิมพ์: 0 คือตัวเลข a คือตัวอักษร * คืออย่างใดอย่างหนึ่ง ส่วนตัวอักษรอื่นเป็นตัวคั่นที่ช่องใส่ให้เอง mask ที่มีแต่ตัวเลขจะเปิดคีย์บอร์ดตัวเลขบนมือถือ ควรเขียนรูปแบบไว้ใน helper text ด้วย ผู้ใช้จะได้รู้ก่อนพิมพ์

max-count แสดงตัวนับไว้เหนือช่อง เป็นขีดจำกัดแบบไม่บังคับ ผู้ใช้วางข้อความยาว ๆ แล้วค่อยตัดทีหลังได้ ถ้าเกิน ตัวนับจะเป็นสีแดง error ขึ้นทันที และฟอร์มส่งไม่ได้ screen reader จะอ่านเตือนเมื่อใกล้ครบ ไม่ได้อ่านทุกครั้งที่พิมพ์

  • ใน element required, pattern, minlength และการตรวจของเบราว์เซอร์ทำงานเหมือน <input> และ error จะรอจนผู้ใช้ออกจากช่อง ส่วนช่องของ React + Tailwind แสดงตามที่คุณส่ง invalid และ invalidText มา การตรวจค่าเป็นหน้าที่ของแอป แบบ Carbon React
  • ถ้าจะใส่ลิงก์ในข้อความ ให้ใช้ slot ชื่อเดียวกัน (helper-text, warn-text, invalid-text) ใน React + Tailwind ส่ง markup ให้ helperText, warnText หรือ invalidText ได้เลย
  • เรื่องจังหวะที่ error ขึ้น custom validity และ error จาก server ดูที่ ฟอร์มและการตรวจค่า

label และข้อความช่วยที่มี markup

ถ้า label หรือข้อความมี markup เช่น ลิงก์หรือตัวเน้น ให้ใช้ slot label และ helper-text (warn-text กับ invalid-text ก็ใช้แบบเดียวกัน) ช่องของ React + Tailwind รับ markup ทาง label และ helperText

ตำแหน่ง label, อ่านอย่างเดียว และปิดใช้งาน

  • hide-label ซ่อน label จากสายตาแต่ screen reader ยังอ่านได้ ใช้เฉพาะเมื่อมีอย่างอื่นบนจอที่บอกอยู่แล้วว่าช่องนี้คืออะไร
  • inline วาง label ไว้หน้าช่องและข้อความไว้หลังช่องในแถวเดียว (inline text input ของ Carbon)
  • fluid หรือการครอบด้วยฟอร์มแบบ fluid ย้าย label เข้าไปในกล่องสูง 64px (ฟอร์มแบบ fluid)
  • readonly แสดงค่าและส่งค่าไปกับฟอร์ม แต่ผู้ใช้แก้ไม่ได้ ส่วน disabled ทำให้ช่องเป็นสีเทาและไม่ส่งค่า

ช่องแบบ fluid

ช่องแบบ fluid วาง label ไว้ในกล่องสูง 64px และแสดง error หรือคำเตือนในกล่องใต้เส้นคั่น ช่องแบบนี้ไม่มี helper text ตั้ง fluid ที่ช่อง หรือครอบช่องทั้งหมดด้วย <ui-fluid-form> (ดู ฟอร์มแบบ fluid)

ตรวจค่าในฟอร์ม

ใน <form> element ตรวจ required, type, pattern, minlength และตัวนับให้เหมือน input ปกติ ถ้ามีช่องที่ไม่ผ่าน ฟอร์มจะส่งไม่ได้ ทุกช่องที่ไม่ผ่านจะแสดง error และช่องแรกจะได้โฟกัส ลองกดส่งฟอร์มนี้โดยไม่กรอกอะไร

Skeleton

ระหว่างที่ข้อมูลของฟอร์มกำลังโหลด <ui-text-input-skeleton> จองที่ของช่องไว้ เป็นแถบ label กับแถบช่องสูงตาม size หรือเป็นกล่องแบบ fluid เมื่อใส่ fluid screen reader ข้ามแถบนี้ จึงต้องบอกว่า "กำลังโหลด" ที่ฟอร์มแทน (เช่น aria-busy="true")

ปุ่ม ผล

Accessibility

  • label เป็น <label> จริงที่ผูกกับ <input> ข้างใน และบรรทัดข้อความใต้ช่องเป็น aria-describedby ของมัน aria-label ที่ตัว element ไปไม่ถึง input ให้ใช้ label แทน (คู่กับ hide-label ถ้าไม่อยากให้เห็น)
  • เมื่อมี error input จะมี aria-invalid ใน element error รอจนผู้ใช้ออกจากช่อง จะได้ไม่มีใครได้ยินคำว่า "ต้องกรอก" ระหว่างที่ยังพิมพ์อยู่
  • ปุ่มรหัสผ่านไม่มี aria-pressed ชื่อปุ่มเปลี่ยนตามสิ่งที่จะเกิดเมื่อกดครั้งถัดไป แบบ Carbon
  • prefix และ suffix ถูกอ่านเป็นส่วนหนึ่งของคำอธิบายช่อง ผู้ใช้ screen reader จึงไม่พลาด "฿" หรือ "กก."

ต้องการแค่พฤติกรรมโดยไม่มี style: Headless Text input
