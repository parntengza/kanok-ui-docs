Text area

A text area takes text that runs over several lines: notes, a description, a reason. It has the same label, helper text and error line as the text input, plus a character or word counter and a field that can grow with its text.

HTMLReactReact + Tailwind<ui-text-area label="Notes" name="notes" helper-text="Anything the legal team should know"></ui-text-area> <UiTextArea label="Notes" name="notes" helperText="Anything the legal team should know" /> <TextArea label="Notes" name="notes" helperText="Anything the legal team should know" />

Use it

HTMLReactReact + Tailwind<script type="module">import '@purpurabog/ui/text-area';</script> <ui-text-area label="Notes" name="notes"></ui-text-area> import { UiTextArea } from '@purpurabog/ui/react'; <UiTextArea label="Notes" name="notes" onInput={(e) => setNotes((e.target as HTMLTextAreaElement).value)} /> import { TextArea } from '@/components/ui/react-tw/text-area'; <TextArea label="Notes" name="notes" value={notes} onChange={(e) => setNotes(e.target.value)} />
  • The element fires native input on every keystroke and change when the user leaves the field, so the React wrapper has onInput and onChange. The React + Tailwind onChange is React's own (every keystroke).

Height

rows sets the starting height in lines, 4 by default as in Carbon. The user can drag the corner to make it taller (resize: vertical); a disabled field can't be resized.

HTMLReactReact + Tailwind<ui-text-area label="Reason for the change" name="reason" rows="2"></ui-text-area> <UiTextArea label="Reason for the change" name="reason" rows={2} /> <TextArea label="Reason for the change" name="reason" rows={2} />

Grow with the text

auto-grow starts at rows and grows a line at a time as the user types, with no resize handle. max-rows caps it; past that, the field scrolls. Carbon has no auto-grow.

HTMLReactReact + Tailwind<ui-text-area label="Description" name="description" rows="2" auto-grow max-rows="6"></ui-text-area> <UiTextArea label="Description" name="description" rows={2} autoGrow maxRows={6} /> <TextArea label="Description" name="description" rows={2} autoGrow maxRows={6} />

Count characters or words

max-count shows a counter above the field. As on the text input, it's a soft limit: going over turns the counter red, shows an error at once and blocks the form, but nothing is cut. Screen readers hear when the limit is near.

counter-mode="word" counts words instead (Carbon's counterMode). Thai has no spaces between words, so the field asks the browser's word segmenter for its language (lang on the field or the page): "สวัสดีครับ ผมชื่อสมชาย" is 5 words, where Carbon's count splits Thai at every vowel and tone mark. Numbers don't count as words.

HTMLReactReact + Tailwind<ui-text-area label="Notes" name="notes" max-count="200"></ui-text-area> <ui-text-area label="Summary" name="summary" max-count="50" counter-mode="word"></ui-text-area> <UiTextArea label="Notes" name="notes" maxCount={200} /> <UiTextArea label="Summary" name="summary" maxCount={50} counterMode="word" /> <TextArea label="Notes" name="notes" maxCount={200} /> <TextArea label="Summary" name="summary" maxCount={50} counterMode="word" />

Change the messages with too-long-text ({max} becomes the limit) and near-limit-text. For a hard limit that stops typing, use maxlength. More in Forms and validation.

Your own counter messages

too-long-text is the error once the text is over the limit, and near-limit-text is what screen readers hear once when 10% or less is left. Write them for the field, so people know what to cut. This text is already too long, so the error shows at once.

HTMLReactReact + Tailwind<ui-text-area label="Reason for rejection" name="rejectReason" rows="2" max-count="60" too-long-text="Keep the reason under {max} characters for the approval email" near-limit-text="Almost at the length the approval email allows" value="The rent is higher than the budget that finance approved for this year."></ui-text-area> <UiTextArea label="Reason for rejection" name="rejectReason" rows={2} maxCount={60} tooLongText="Keep the reason under {max} characters for the approval email" nearLimitText="Almost at the length the approval email allows" /> <TextArea label="Reason for rejection" name="rejectReason" rows={2} maxCount={60} tooLongText="Keep the reason under {max} characters for the approval email" nearLimitText="Almost at the length the approval email allows" />

Helper text, warnings and errors

Same as the text input: one line under the field, an error beats a warning, and a warning beats the helper text. The error and warning icons sit in the top-right corner of the field.

HTMLReactReact + Tailwind<ui-text-area label="Delivery address" name="address" value="99/1 Rama IV Rd" warn warn-text="Add the district and postcode"></ui-text-area> <ui-text-area label="Reason" name="reason" invalid invalid-text="Tell us why the contract ends early"></ui-text-area> <UiTextArea label="Delivery address" name="address" value="99/1 Rama IV Rd" warn warnText="Add the district and postcode" /> <UiTextArea label="Reason" name="reason" invalid invalidText="Tell us why the contract ends early" /> <TextArea label="Delivery address" name="address" defaultValue="99/1 Rama IV Rd" warn warnText="Add the district and postcode" /> <TextArea label="Reason" name="reason" invalid invalidText="Tell us why the contract ends early" />

required, minlength and maxlength work on the element as on <textarea>. In React + Tailwind, validation is your app's: pass invalid and invalidText. Everything else about errors: Forms and validation.

Label and helper text with markup

For a label or a message with markup, use the label and helper-text slots (warn-text and invalid-text work the same way). The React + Tailwind field takes the markup in label and helperText.

Scope of work (part of the contract) Put each service on its own line
HTMLReactReact + Tailwind<ui-text-area name="scope" rows="3"> <span slot="label">Scope of work <em>(part of the contract)</em></span> <span slot="helper-text">Put each service on <strong>its own line</strong></span> </ui-text-area> <UiTextArea name="scope" rows={3}> <span slot="label">Scope of work <em>(part of the contract)</em></span> <span slot="helper-text">Put each service on <strong>its own line</strong></span> </UiTextArea> <TextArea name="scope" rows={3} label={<>Scope of work <em>(part of the contract)</em></>} helperText={<>Put each service on <strong>its own line</strong></>} />

Read-only, disabled and fluid

  • readonly shows and submits the text, but the user can't change it. disabled greys it out; it isn't submitted.
  • fluid, or a fluid form around it, puts the label inside the box (Carbon's FluidTextArea, see fluid forms).
HTMLReactReact + Tailwind<ui-text-area label="Terms" value="Rent is paid on the first working day of each month." readonly></ui-text-area> <ui-text-area label="Notes from legal" value="Reviewed on 2 October." rows="2" disabled></ui-text-area> <ui-text-area label="Notes" name="notes" fluid></ui-text-area> <UiTextArea label="Terms" value="Rent is paid on the first working day of each month." readonly /> <UiTextArea label="Notes from legal" value="Reviewed on 2 October." rows={2} disabled /> <UiTextArea label="Notes" name="notes" fluid /> <TextArea label="Terms" defaultValue="Rent is paid on the first working day of each month." readOnly /> <TextArea label="Notes from legal" defaultValue="Reviewed on 2 October." rows={2} disabled /> <TextArea label="Notes" name="notes" fluid />

Outlined (Kanok design)

In the Kanok design, fields are filled by default: a soft grey fill, no edge. Put data-field-variant="outlined" on an element around the field (a <form>, or <html> for the whole app) for a 1px edge on no fill; focus is still the soft blue halo. The attribute does nothing in the Carbon design, so the example below sits inside data-design="kanok". See Kanok design for the details.

HTMLReactReact + Tailwind<div data-design="kanok" data-theme="paper" data-field-variant="outlined"> <ui-text-area label="Notes" name="notes" helper-text="Anything the legal team should know"></ui-text-area> </div> <div data-field-variant="outlined"> <UiTextArea label="Notes" name="notes" helperText="Anything the legal team should know" /> </div> <div data-field-variant="outlined"> <TextArea label="Notes" name="notes" helperText="Anything the legal team should know" /> </div>

Check it in a form

In a <form>, required and minlength block the submit until the text is long enough, and the field shows its error. Try sending this form with a short reason.

Send for approval

Save a draft when the user leaves

change fires once the user leaves the field after changing it, so it is the moment to save a draft without a request on every keystroke.

Draft: not saved yet

HTMLReactReact + Tailwind<ui-text-area id="text-area-draft" label="Meeting notes" name="minutes" rows="3"></ui-text-area> <p>Draft: <output id="text-area-draft-out">not saved yet</output></p> <script type="module"> const minutes = document.getElementById('text-area-draft'); minutes.addEventListener('change', () => { const time = new Date().toLocaleTimeString('en', { hour: '2-digit', minute: '2-digit' }); document.getElementById('text-area-draft-out').textContent = `saved at ${time}, ${minutes.value.length} characters`; }); </script> <UiTextArea label="Meeting notes" name="minutes" rows={3} onChange={(e) => saveDraft((e.target as HTMLTextAreaElement).value)} /> // onChange runs on every keystroke here: save when the field loses focus <TextArea label="Meeting notes" name="minutes" rows={3} onBlur={(e) => saveDraft(e.target.value)} />

Skeleton

While the data of a form loads, <ui-text-area-skeleton> keeps the field's place: a label bar and a 100px field bar, or a fluid box with fluid. Screen readers skip it, so say "loading" on the form (for example aria-busy="true").

HTMLReactReact + Tailwind<ui-text-area-skeleton></ui-text-area-skeleton> <ui-text-area-skeleton fluid></ui-text-area-skeleton> import { UiTextAreaSkeleton } from '@purpurabog/ui/react'; <UiTextAreaSkeleton /> <UiTextAreaSkeleton fluid /> import { TextAreaSkeleton } from '@/components/ui/react-tw/text-area'; <TextAreaSkeleton /> <TextAreaSkeleton fluid />

Accessibility

  • The label is a real <label> for the inner <textarea>, and the message line is its aria-describedby. aria-label on the element does not reach the textarea; use label (with hide-label if it must not show).
  • Enter types a new line, as in any text area; it never submits the form.
  • The counter is not read on every keystroke. Screen readers hear once when the limit is near and when it's passed.

Unstyled React parts with the same behaviour: Headless Text area.

API

Generated from the package. In React, pass a property as a prop of the same name; events are props too (the React column).

Attributes

Attribute Property Type Default Description
label label string '' Visible label text; the label slot replaces it when markup is needed.
hide-label hideLabel boolean false Keep the label for screen readers but don't show it.
helper-text helperText string '' Helper text under the field, shown while there is no error or warning.
invalid-text invalidText string '' Error text shown while invalid or while the field fails validation.
invalid invalid boolean false Forces the error state, e.g. after server-side validation.
warn warn boolean false Non-blocking warning; shown when there is no error.
warn-text warnText string '' Text of the warning shown while warn.
value value string ''
name name string '' Reflected: form-associated elements submit under the name attribute.
placeholder placeholder string ''
rows rows number 4 Initial number of text rows (Carbon default 4); the user can still resize.
minlength minlength number | undefined
maxlength maxlength number | undefined
autocomplete autocomplete string '' Passed to the textarea (off, or an autofill token).
inputmode inputmode string '' Passed to the text box: the virtual keyboard to show (numeric, decimal, email, tel, url, search…).
enterkeyhint enterkeyhint string '' Passed to the text box: the label of the virtual keyboard's Enter key (search, send, next, done…).
max-count maxCount number | undefined Soft limit with a visible counter (unlike maxlength, extra text isn't blocked).
counter-mode counterMode CounterMode 'character' What max-count counts: character (default) or word (Carbon counterMode).
auto-grow autoGrow boolean false Grows with the text from rows (no Carbon counterpart); max-rows caps it, then it scrolls.
max-rows maxRows number | undefined The most lines auto-grow shows before scrolling (default: no cap).
too-long-text tooLongText string '' Error when over max-count; {max} is replaced with the limit (default: the translation's, for characters or words).
near-limit-text nearLimitText string '' Announced once when what is left of the limit drops to 10% or less.
disabled disabled boolean false Disables the control; a disabled <fieldset> ancestor does the same.
readonly readonly boolean false Shows and submits the value but blocks changes.
fluid fluid boolean false Carbon FluidTextArea: the label inside a 64px box, an error / warning inside it. <ui-fluid-form> sets it for every field inside.
required required boolean false Blocks form submission while the field is empty.

Properties

Property Type Description
willValidate (read-only) Whether the field takes part in constraint validation (not while disabled), as natively.
labels (read-only) The <label>s that point at this field.

Methods

Method Description
setCustomValidity(message) Like <input>.setCustomValidity(): a non-empty message makes the field invalid (and is shown as its error once touched) until cleared with ''.

Events

Event React Description
change onChange Re-dispatched from the native textarea (native change is not composed)
input onInput Native input event (already composed, so it reaches the host)

Slots

Slot Description
label Label content with markup; the label attribute is the plain-text fallback
helper-text Helper text with markup (links, bold); overrides helper-text
warn-text Warning text shown while warn; overrides warn-text
invalid-text Error text shown while invalid; overrides invalid-text
