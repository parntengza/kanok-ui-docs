Text input

A text input takes one line of text: a name, an email, a password, an ID number. For several lines, use a text area; for amounts, a number input.

HTMLReactReact + Tailwind<ui-text-input label="Full name" name="name" helper-text="As it appears on your ID card"></ui-text-input> <ui-text-input label="Password" name="password" type="password"></ui-text-input> <UiTextInput label="Full name" name="name" helperText="As it appears on your ID card" /> <UiTextInput label="Password" name="password" type="password" /> <TextInput label="Full name" name="name" helperText="As it appears on your ID card" /> <TextInput label="Password" name="password" type="password" />

Use it

HTMLReactReact + Tailwind<script type="module">import '@purpurabog/ui/text-input';</script> <ui-text-input label="Full name" name="name"></ui-text-input> import { UiTextInput } from '@purpurabog/ui/react'; <UiTextInput label="Full name" name="name" onInput={(e) => setName((e.target as HTMLInputElement).value)} /> import { TextInput } from '@/components/ui/react-tw/text-input'; <TextInput label="Full name" name="name" value={name} onChange={(e) => setName(e.target.value)} />
  • The element fires native input on every keystroke and change when the user commits the value, so the React wrapper has onInput and onChange.
  • The React + Tailwind onChange is React's own (every keystroke). Its second argument is the value without a mask's separators.

Passwords

type="password" adds Carbon's show / hide button at the end of the field. Its tooltip is also its name and says what a press does next: "Show password", then "Hide password". Change the words with show-password-label and hide-password-label. Each press fires ui-toggle with detail.visible.

Password shown: no

Email, phone and web addresses

type also takes email, tel, url, search and number, as on <input>. For the virtual keyboard alone, set inputmode (and enterkeyhint for its Enter key).

Add autocomplete so the browser can fill the field in. The browser checks an email address; a mask keeps a phone number readable.

Currency, units and masks

prefix-text and suffix-text put text inside the field, before or after the value: a currency, a unit. They aren't part of the value, and screen readers hear them as part of the field's description.

mask formats the value as the user types: 0 is a digit, a a letter, * either, and any other character is a separator the field adds by itself. A mask of digits only brings up the numeric keyboard. Put the format in the helper text too, so people know it before they type.

HTMLReactReact + Tailwind<ui-text-input label="Weight" name="weight" suffix-text="kg"></ui-text-input> <ui-text-input label="Citizen ID" name="citizenId" mask="0-0000-00000-00-0" helper-text="13 digits: 0-0000-00000-00-0"></ui-text-input> <UiTextInput label="Weight" name="weight" suffixText="kg" /> <UiTextInput label="Citizen ID" name="citizenId" mask="0-0000-00000-00-0" helperText="13 digits: 0-0000-00000-00-0" /> <TextInput label="Weight" name="weight" suffixText="kg" /> <TextInput label="Citizen ID" name="citizenId" mask="0-0000-00000-00-0" helperText="13 digits: 0-0000-00000-00-0" onChange={(e, raw) => setCitizenId(raw)} />
  • The element's value and the submitted form get the formatted text (1-2345-67890-12-3). Its rawValue property gives what was typed, without separators (1234567890123). In React + Tailwind, onChange gets that as its second argument.
  • A value your code sets, raw or formatted, shows formatted.
  • None of these has a Carbon counterpart (Carbon puts the unit or the format in the label or helper text); they follow USWDS.

Character counter

max-count shows a counter above the field. It's a soft limit: people can paste a long text and then trim it. Going over turns the counter red, shows an error at once and blocks the form. Screen readers hear when the limit is near, not on every keystroke.

HTMLReactReact + Tailwind<ui-text-input label="Contract title" name="title" max-count="40" value="Lease of the warehouse on Rama IV Road"></ui-text-input> <UiTextInput label="Contract title" name="title" maxCount={40} value="Lease of the warehouse on Rama IV Road" /> <TextInput label="Contract title" name="title" maxCount={40} defaultValue="Lease of the warehouse on Rama IV Road" />

Change the messages with too-long-text ({max} becomes the limit) and near-limit-text. For a hard limit that stops typing, use maxlength. More in Forms and validation.

Helper text, warnings and errors

One line shows under the field at a time: an error beats a warning, and a warning beats the helper text.

HTMLReactReact + Tailwind<ui-text-input label="Phone" name="phone" helper-text="We only call about this contract"></ui-text-input> <ui-text-input label="Email" name="email" value="somchai@gmial.com" warn warn-text="Check the spelling of the domain"></ui-text-input> <ui-text-input label="Tax ID" name="taxId" value="12345" invalid invalid-text="A tax ID has 13 digits"></ui-text-input> <UiTextInput label="Phone" name="phone" helperText="We only call about this contract" /> <UiTextInput label="Email" name="email" value="somchai@gmial.com" warn warnText="Check the spelling of the domain" /> <UiTextInput label="Tax ID" name="taxId" value="12345" invalid invalidText="A tax ID has 13 digits" /> <TextInput label="Phone" name="phone" helperText="We only call about this contract" /> <TextInput label="Email" name="email" defaultValue="somchai@gmial.com" warn warnText="Check the spelling of the domain" /> <TextInput label="Tax ID" name="taxId" defaultValue="12345" invalid invalidText="A tax ID has 13 digits" />
  • On the element, required, pattern, minlength and the browser's checks work as on <input>, and their errors wait until the user leaves the field. The React + Tailwind field shows what you pass in invalid and invalidText; validation is your app's, as in Carbon React.
  • To put a link in a message, use the slot of the same name (helper-text, warn-text, invalid-text). In React + Tailwind, pass the markup to helperText, warnText or invalidText.
  • When errors show, custom validity and server errors: Forms and validation.

Label and helper text with markup

For a label or a message with markup, such as a link or an emphasis, use the label and helper-text slots (warn-text and invalid-text work the same way). The React + Tailwind field takes the markup in label and helperText.

Label position, read-only and disabled

  • hide-label keeps the label for screen readers but doesn't show it. Use it only where something else on screen names the field.
  • inline puts the label before the field and the message after it, in one row (Carbon's inline text input).
  • fluid, or a fluid form around the field, puts the label inside a 64px box (fluid forms).
  • readonly shows and submits the value, but the user can't change it. disabled greys the field out; it isn't submitted.
HTMLReactReact + Tailwind<ui-text-input label="Contract no." value="C-2026-0142" inline></ui-text-input> <ui-text-input label="Contract no." value="C-2026-0142" readonly></ui-text-input> <ui-text-input label="Branch" value="Bangkok" disabled></ui-text-input> <UiTextInput label="Contract no." value="C-2026-0142" inline /> <UiTextInput label="Contract no." value="C-2026-0142" readonly /> <UiTextInput label="Branch" value="Bangkok" disabled /> <TextInput label="Contract no." defaultValue="C-2026-0142" inline /> <TextInput label="Contract no." defaultValue="C-2026-0142" readOnly /> <TextInput label="Branch" defaultValue="Bangkok" disabled />

Fluid fields

A fluid field puts its label inside a 64px box, and an error or a warning shows inside the box below a line; there is no helper text. Set fluid on a field, or put the fields in a <ui-fluid-form> (see fluid forms).

HTMLReactReact + Tailwind<ui-text-input label="Contract value" name="amount" prefix-text="฿" suffix-text="THB" value="500,000" fluid></ui-text-input> <ui-text-input label="Password" name="password" type="password" fluid></ui-text-input> <UiTextInput label="Contract value" name="amount" prefixText="฿" suffixText="THB" value="500,000" fluid /> <UiTextInput label="Password" name="password" type="password" fluid /> <TextInput label="Contract value" name="amount" prefixText="฿" suffixText="THB" defaultValue="500,000" fluid /> <TextInput label="Password" name="password" type="password" fluid />

Outlined (Kanok design)

In the Kanok design, fields are filled by default: a soft grey fill, no edge. Put data-field-variant="outlined" on an element around the field (a <form>, or <html> for the whole app) for a 1px edge on no fill; focus is still the soft blue halo. The attribute does nothing in the Carbon design, so the example below sits inside data-design="kanok". See Kanok design for the details.

Check it in a form

In a <form>, the element checks required, type, pattern, minlength and the counter, as a native input does. A submit with a problem is blocked, every field with a problem shows its error, and the first one gets focus. Try sending this form empty.

Errors from your own checks

setCustomValidity(message) makes the field invalid with your message, as on <input>. Use it for a check the browser can't do, such as a contract number that is already in use. The error shows once the user leaves the field; setCustomValidity('') clears it. More in Forms and validation.

Skeleton

While the data of a form loads, <ui-text-input-skeleton> keeps the field's place: a label bar and a field bar at its size, or a fluid box with fluid. Screen readers skip it, so say "loading" on the form (for example aria-busy="true").

Accessibility

  • The label is a real <label> for the inner <input>, and the message line is its aria-describedby. aria-label on the element does not reach the input; use label (with hide-label if it must not show).
  • An error sets aria-invalid on the input. On the element it waits until the user leaves the field, so nobody hears "required" while still typing.
  • The password button has no aria-pressed: its name changes with what it does next, as in Carbon.
  • The prefix and suffix are read as part of the field's description, so "฿" or "kg" isn't lost to screen reader users.

Unstyled React parts with the same behaviour: Headless Text input.
