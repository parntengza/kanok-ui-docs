Combobox

A combobox is a text box with a list: people type to find an option instead of scrolling. Use it for long lists, server lookups, and fields that also take free text.

How typing narrows the list

Typing opens the list and highlights the first option whose label contains the text. filter decides whether the other options stay:

filter The list while typing
none (default, as Carbon) Every option stays; only the highlight moves
contains Only options whose label contains the text, anywhere
starts-with Only options whose label starts with the text

Matching ignores case. When the filter leaves no option, the list shows "No matching items". Type "chiang" in both fields below to compare.

HTMLReactReact + Tailwind<ui-combobox label="Province (filter none)" placeholder="Type a province"> <option value="bkk">Bangkok</option> <option value="cnx">Chiang Mai</option> <option value="cri">Chiang Rai</option> <option value="hkt">Phuket</option> </ui-combobox> <ui-combobox label="Province (filter starts-with)" placeholder="Type a province" filter="starts-with"> <option value="bkk">Bangkok</option> <option value="cnx">Chiang Mai</option> <option value="cri">Chiang Rai</option> <option value="hkt">Phuket</option> </ui-combobox> <UiCombobox label="Province (filter none)" placeholder="Type a province">…</UiCombobox> <UiCombobox label="Province (filter starts-with)" placeholder="Type a province" filter="starts-with">…</UiCombobox> <Combobox label="Province (filter none)" placeholder="Type a province" items={provinces} /> <Combobox label="Province (filter starts-with)" placeholder="Type a province" items={provinces} filter="starts-with" />

Free text or a listed option

When the user leaves the field, text that exactly matches an option's label picks that option. Other text snaps back to the option chosen before, so the value is always one of the options.

allow-custom-value keeps the typed text instead: it becomes the value and is submitted with the form. Use it when the list is only a suggestion, such as job titles.

HTMLReactReact + Tailwind<ui-combobox label="Job title" name="title" allow-custom-value helper-text="Pick a title or type a new one"> <option value="Lawyer">Lawyer</option> <option value="Paralegal">Paralegal</option> <option value="Legal secretary">Legal secretary</option> </ui-combobox> <UiCombobox label="Job title" name="title" allowCustomValue helperText="Pick a title or type a new one"> <option value="Lawyer">Lawyer</option> <option value="Paralegal">Paralegal</option> <option value="Legal secretary">Legal secretary</option> </UiCombobox> const titles = [ { value: 'Lawyer', label: 'Lawyer' }, { value: 'Paralegal', label: 'Paralegal' }, { value: 'Legal secretary', label: 'Legal secretary' }, ]; <Combobox label="Job title" name="title" items={titles} allowCustomValue helperText="Pick a title or type a new one" />

Search on a server

Listen to the text as the user types, fetch the matches, replace the options, and set loading while the request runs. The list shows "Searching…" meanwhile. Keep filter="none" (the default), as the server has already filtered. In the demo, a short timer stands in for the server.

HTMLReactReact + Tailwind<ui-combobox id="combobox-company" label="Counterparty" name="company" placeholder="Type a company name" helper-text="Searches the company register as you type"></ui-combobox> <script type="module"> // stands in for fetch(`/api/companies?q=${encodeURIComponent(text)}`).then((response) => response.json()) const register = ['Siam Trading Co., Ltd.', 'Siam Logistics PCL', 'Chao Phraya Holdings Co., Ltd.', 'Lanna Foods Co., Ltd.', 'Andaman Resorts Co., Ltd.']; const search = (text) => new Promise((resolve) => setTimeout(() => resolve(register.filter((name) => name.toLowerCase().includes(text.toLowerCase()))), 600), ); const company = document.getElementById('combobox-company'); company.addEventListener('input', async () => { const text = company.inputValue; company.loading = true; const found = await search(text); if (company.inputValue !== text) return; // a newer search is running company.replaceChildren(...found.map((name) => new Option(name, name))); company.loading = false; }); </script> const [companies, setCompanies] = useState<string[]>([]); const [loading, setLoading] = useState(false); const onText = async (text: string) => { setLoading(true); setCompanies(await search(text)); setLoading(false); }; <UiCombobox label="Counterparty" name="company" placeholder="Type a company name" loading={loading} onInput={(e) => onText((e.target as ComboboxElement).inputValue)}> {companies.map((name) => <option key={name} value={name}>{name}</option>)} </UiCombobox> <Combobox label="Counterparty" name="company" placeholder="Type a company name" items={companies.map((name) => ({ value: name, label: name }))} loading={loading} onInputChange={onText} />

companies, loading, onText and search are the same in every React version.

Groups and descriptions

As in Dropdown: <optgroup label> groups options, data-description adds a second line, and disabled options are shown but can't be picked. React + Tailwind takes groups { label, options } and description in items. Typing only searches the labels, never the descriptions.

Clear

While the box holds text, × clears it along with the value. hide-clear removes the × (Carbon always shows it). Esc on a closed list still clears.

Outlined (Kanok design)

Helper text, warnings and errors

One line shows under the field at a time: an error beats a warning, and a warning beats the helper text. warn doesn't block the form; invalid forces the error.

Required in a form

required blocks the form until a value is committed. The error waits until the user leaves the field or submits. Press Submit with the field empty to see it.

Keyboard

Key Does
Typing Opens the list and highlights the first option containing the text
↓ / ↑ Opens the list on the chosen option (else the first / last); then moves the highlight (no wrap)
Alt+↓ Opens the list without a highlight
Alt+↑ Picks the highlighted option and closes
Enter Picks the highlighted option. With no highlight, picks the first option containing the text (or keeps the text with allow-custom-value)
Esc Closes the list; on a closed list, clears the field
Tab Moves on without picking the highlight. The text is committed or snaps back, as described above

Accessibility

  • It follows the WAI-ARIA combobox pattern with list autocomplete: the text box has role="combobox", the list is a listbox, and the highlight is announced through aria-activedescendant.
  • The × and the chevron are not Tab stops (as in Carbon), so Tab goes straight to the next field. Esc clears from the keyboard.
  • "Searching…" and "No matching items" are announced to screen readers.
