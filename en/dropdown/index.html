Dropdown

A dropdown picks one option from a list that looks the same in every browser. Options can have a second line and sit in labelled groups.

HTMLReactReact + Tailwind<ui-dropdown label="Contract type" name="type" placeholder="Choose a type"> <option value="sale" data-description="The buyer owns the property">Sale</option> <option value="lease" data-description="Monthly rent, fixed term">Lease</option> <option value="mortgage" data-description="Property as security for a loan">Mortgage</option> </ui-dropdown> <UiDropdown label="Contract type" name="type" placeholder="Choose a type"> <option value="sale" data-description="The buyer owns the property">Sale</option> <option value="lease" data-description="Monthly rent, fixed term">Lease</option> <option value="mortgage" data-description="Property as security for a loan">Mortgage</option> </UiDropdown> const types = [ { value: 'sale', label: 'Sale', description: 'The buyer owns the property' }, { value: 'lease', label: 'Lease', description: 'Monthly rent, fixed term' }, { value: 'mortgage', label: 'Mortgage', description: 'Property as security for a loan' }, ]; <Dropdown label="Contract type" name="type" placeholder="Choose a type" items={types} />

Select, Dropdown, Combobox or MultiSelect?

Component Use it when
Select A plain form field. The browser draws the list: the native picker on phones, the most familiar control for screen readers.
Dropdown The list must look the same in every browser, or options need a second line.
Combobox The list is long and typing is faster than scrolling, the options come from a server search, or free text is allowed.
Multi-select The user picks several values.

Options, groups and descriptions

The web component takes <option value> children, the same markup as Select:

  • <optgroup label> makes a labelled group in the list.
  • data-description on an option adds a second line under its label. Typing to jump to an option only searches the label.
  • disabled shows an option but skips it.

React + Tailwind takes the same as data in items: options { value, label, description?, disabled? } and groups { label, options }.

HTMLReactReact + Tailwind<ui-dropdown label="Branch" name="branch" placeholder="Choose a branch"> <optgroup label="Bangkok"> <option value="silom" data-description="Mon–Fri, 9:00–17:00">Silom</option> <option value="asok" data-description="Every day, 10:00–20:00">Asok</option> </optgroup> <optgroup label="North"> <option value="chiangmai">Chiang Mai</option> <option value="lampang" disabled>Lampang (closed)</option> </optgroup> </ui-dropdown> <UiDropdown label="Branch" name="branch" placeholder="Choose a branch"> <optgroup label="Bangkok"> <option value="silom" data-description="Mon–Fri, 9:00–17:00">Silom</option> <option value="asok" data-description="Every day, 10:00–20:00">Asok</option> </optgroup> <optgroup label="North"> <option value="chiangmai">Chiang Mai</option> <option value="lampang" disabled>Lampang (closed)</option> </optgroup> </UiDropdown> const branches = [ { label: 'Bangkok', options: [ { value: 'silom', label: 'Silom', description: 'Mon–Fri, 9:00–17:00' }, { value: 'asok', label: 'Asok', description: 'Every day, 10:00–20:00' }, ] }, { label: 'North', options: [ { value: 'chiangmai', label: 'Chiang Mai' }, { value: 'lampang', label: 'Lampang (closed)', disabled: true }, ] }, ]; <Dropdown label="Branch" name="branch" placeholder="Choose a branch" items={branches} />

Placeholder and value

placeholder is the text in the field while nothing is chosen (Carbon calls it label). The starting choice is value, else the <option selected>. Reset goes back to it. change fires when the user picks a different option.

Value:

React + Tailwind also takes defaultValue when you don't need to hold the value yourself.

Sizes and direction

size: sm 32px, md 40px (the default), lg 48px. The list opens below the field. direction="top" prefers above; either way it flips when there is no room.

Inline

inline puts the label, a borderless field and any error or warning in one row, with no helper line. Use it in toolbars and above tables.

Fluid

Outlined (Kanok design)

In the Kanok design, fields are filled by default: a soft grey fill, no edge. Put data-field-variant="outlined" on an element around the field (a <form>, or <html> for the whole app) for a 1px edge on no fill; focus is still the soft blue halo. The attribute does nothing in the Carbon design, so the example below sits inside data-design="kanok". See Kanok design for the details.

Load the options when the list opens

loading shows one "Loading…" row instead of the options, and the keys pick nothing. Together with the event that fires after the list opens or closes, you can fetch the options the first time someone opens the list. Open the list below: the names arrive after a second.

HTMLReactReact + Tailwind<ui-dropdown id="dropdown-owner" label="Contract owner" name="owner" placeholder="Choose an owner" helper-text="The names load the first time the list opens" loading></ui-dropdown> <script type="module"> // stands in for fetch('/api/owners').then((response) => response.json()) const loadOwners = () => new Promise((resolve) => setTimeout(() => resolve([ { value: 'anong', label: 'Anong P.' }, { value: 'boonmee', label: 'Boonmee S.' }, { value: 'chaiya', label: 'Chaiya R.' }, ]), 1000), ); const owner = document.getElementById('dropdown-owner'); owner.addEventListener('ui-toggle', async (event) => { if (!event.detail.open || !owner.loading) return; const owners = await loadOwners(); owner.replaceChildren(...owners.map((o) => new Option(o.label, o.value))); owner.loading = false; }); </script> const [owners, setOwners] = useState<{ value: string; label: string }[]>(); const load = async (open: boolean) => { if (open && !owners) setOwners(await loadOwners()); }; <UiDropdown label="Contract owner" name="owner" placeholder="Choose an owner" helperText="The names load the first time the list opens" loading={!owners} onUiToggle={(e) => load(e.detail.open)}> {owners?.map((o) => <option key={o.value} value={o.value}>{o.label}</option>)} </UiDropdown> <Dropdown label="Contract owner" name="owner" placeholder="Choose an owner" helperText="The names load the first time the list opens" items={owners ?? []} loading={!owners} onMenuChange={load} />

loadOwners, load and owners are the same in every React version.

Read-only and disabled

  • readonly (readOnly in React + Tailwind) shows the value and submits it, but the list doesn't open.
  • disabled greys the field out. It isn't submitted.

Required in a form

An empty required dropdown blocks the form and has a built-in message in Thai and English; invalid-text replaces it. The error waits until the user leaves the field or submits. Press Submit without a choice to see it.

Skeleton

While the options load, show ui-dropdown-skeleton in the field's place: a label bar and a field bar at the same size. It is hidden from screen readers, so say "loading" on the container (for example aria-busy).

Accessibility

  • It follows the WAI-ARIA select-only combobox pattern: the field is a button with role="combobox", the list a listbox. Focus stays on the field and the highlighted option is announced through aria-activedescendant.
  • The field is a Tab stop in every browser, Safari included.
  • loading marks the list busy and announces "Loading…".
  • Use hide-label only when the context already names the field. The label then stays for screen readers.

Unstyled React parts with the same behaviour: Headless Dropdown.

Attributes

Attribute Property Type Default Description

invalid-text invalidText string '' Error text shown while invalid or while the field fails validation.
invalid invalid boolean false Forces the error state, e.g. after server-side validation.
warn warn boolean false Non-blocking warning; shown when there is no error.
warn-text warnText string '' Text of the warning shown while warn.

value value string ''
